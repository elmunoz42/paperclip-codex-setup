# Roadmap

## Five workstreams

| Workstream | Near-term outcome | Boundary |
| --- | --- | --- |
| 1. Agent headquarters & infrastructure | Reliable, documented operating system and safe persistence plan | No production or infrastructure changes |
| 2. YouTube news/show production | One repeatable, review-ready episode package | No publication without Carlos |
| 3. Math for Programmers with Python | Course map and one validated lesson package | No broad curriculum build before the pilot |
| 4. WordPress publishing & commerce | Inventory and integration decision memo | Do not modify the live site |
| 5. Immersive solar-system app & CMS integration | Repo/access discovery and a scoped audit | Do not import app code here or deploy |

## First 30 days — prove the engine

1. Ship one review-ready content thin slice with sources, script, and companion outline.
2. Capture Carlos's review notes and turn them into a compact editorial rubric.
3. Define the Math for Programmers course promise, learner profile, and first 4–6 lesson sequence; pilot one lesson outline.
4. Inventory WordPress capabilities and the immersive application only after access details are provided.
5. Prepare, but do not activate, a Paperclip systemd migration.

## Days 31–60 — repeat and connect

1. Complete two additional reviewed episode packages using the rubric.
2. Turn the Math pilot into a video/script, notebook outline, and article structure.
3. Produce a WordPress integration recommendation: content types, editorial handoff, commerce assumptions, and non-production test plan.
4. Produce an immersive-app audit with performance, responsive UX, visual, CMS, and production-readiness findings.

## Days 61–90 — scale only what worked

1. Establish a sustainable production cadence based on actual review and recording throughput.
2. Package the first Math module and supporting resources.
3. Prioritize one approved WordPress improvement and one approved immersive-app thin slice in their own repositories.
4. Activate Paperclip persistence only after a reviewed maintenance window and rollback rehearsal.

## Sequencing rule

The content workflow is the priority. Product-platform work remains discovery and decision work until its repositories, access, and objectives are supplied.
